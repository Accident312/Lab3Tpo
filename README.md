1) Какие события активируют пайплайн?

    Пайплайн активируется двумя типами событий:
        push - при каждом отправке коммитов
        pull_request - при создании или обновлении Pull Request
2) Будет ли пайплайн с тестами запускаться заново, если разработчик изменил только файл README.md или документацию?

    Да, будет. В базовой конфигурации, которую мы использовали, триггер push срабатывает на любое изменение в ветке.

3) Как и где в конфигурационном файле GitHub Actions (YAML) вы указываете установку зависимостей для прогона тестов?

    Python
        - name: Install dependencies
    run: |
        python -m pip install --upgrade pip
        pip install -r requirements.txt

    Java
        - name: Run tests with coverage check
        run: mvn -B verify

5) Всегда ли есть необходимость 100%-ого покрытия тестами?

    100%-ое покрытие конечно  хорошо, ведь покрыты все функции и исходы, но чем больше тестов, тем сложнее рефакторинг - различные изменения требуют изменения тестов.

6) Какой стек технологий и фреймворк автоматизации используется?
    GitHub Actions - Автоматический запуск тестов при push/PR
    pytest (Python) / JUnit 5 (Java) - Написание и запуск модульных тестов
    Python 3.11 / Java 21 - Реализация бизнес-логики
    Maven - запуск тестов и JaCoCo
